# Recharger Energy — เว็บไซต์ต้นแบบ (UI/UX Prototype)

ต้นแบบเว็บไซต์สำหรับ **Recharger Energy** แพลตฟอร์มที่ทำสองเรื่องพร้อมกัน
คือรวมข้อมูลสถานีชาร์จรถ EV ทั่วประเทศไทย และรับออกแบบ–ติดตั้งเครื่องชาร์จให้บ้านและธุรกิจ

> **สถานะ: ต้นแบบสำหรับทบทวนโครงสร้างข้อมูลและทิศทางงานออกแบบ**
> ข้อมูลเกือบทั้งหมดเป็น mock data — ดูหัวข้อ [ข้อมูลที่ต้องเปลี่ยนก่อนใช้จริง](#ข้อมูลที่ต้องเปลี่ยนก่อนใช้จริง)

## เริ่มใช้งาน

```bash
pnpm install
pnpm dev
```

เปิด http://localhost:3000

```bash
pnpm build   # ตรวจว่า build ผ่านและสร้างหน้า static ครบ
pnpm lint    # ESLint
```

**ต้องต่ออินเทอร์เน็ต** เพื่อให้รูปประกอบขึ้น (ดึงจาก Unsplash)
ส่วนฟอนต์โหลดจากในโปรเจกต์ ไม่ต้องต่อเน็ต

### การนำทาง

- **Desktop** — เมนู 5 ตัว โดย "บทความ" ยุบเป็นเมนูย่อยใต้ "วิธีใช้งาน" + ปุ่ม CTA ขอใบเสนอราคา
- **Mobile** — แฮมเบอร์เกอร์เปิดเมนูเต็มจอ **และ** แถบเมนูล่างจอ 5 ช่อง
  `หน้าแรก · ติดตั้ง · ค้นหา · วิธีใช้งาน · ติดต่อ`
  เป็นการ์ดลอยขอบมน เว้นขอบทั้งสองข้างและด้านล่าง ไอคอนอยู่บนชื่อเมนู
  ช่องที่เลือกอยู่เน้นด้วยวงกลมสีอ่อนหลังไอคอนและตัวหนังสือเข้มขึ้น

  สองเรื่องที่ต้องระวังกับแถบแบบลอย:

  1. **พื้นที่รอบการ์ดต้องโปร่งและกดทะลุได้** — กล่องนอกตั้ง `pointer-events: none`
     แล้วเปิดเฉพาะตัวการ์ด ไม่งั้นแถบใสที่มองไม่เห็นจะไปบังไม่ให้กดของที่อยู่ข้างหลัง
  2. **ที่ว่างที่หน้าอื่นเผื่อไว้ ต้องรวมระยะขอบล่างด้วย** ไม่ใช่แค่ความสูงการ์ด

  ค่ารวมเก็บไว้ที่ตัวแปรเดียว `--rc-dock-h` (ความสูงการ์ด 4.25rem + ขอบล่าง 0.75rem = 5rem)
  ใช้ร่วมกันทั้งตัวแถบเองและที่ว่างที่หน้าอื่นต้องเผื่อ
  **ถ้าจะเปลี่ยนขนาด ให้แก้ที่ตัวแปรนี้ที่เดียว** ไม่งั้นแถบจะไปทับเนื้อหาท้ายหน้า
- **Footer** — ไม่แสดงบนมือถือทุกหน้า เพื่อให้ใช้งานเหมือนแอปมากที่สุด
  และ**ไม่แสดงบนหน้า `/stations` ทั้งบนคอมและมือถือ** เพราะหน้านั้นสูงเท่าหน้าจอพอดี
  ถ้ามี footer ต่อท้ายจะเกิดแถบเลื่อน แล้วการหมุนล้อจะกลายเป็นการเลื่อนหน้าแทนการซูมแผนที่
  (ดู `src/components/layout/FooterSlot.tsx`) ข้อมูลติดต่อทั้งหมดอยู่ที่หน้า `/contact` อยู่แล้ว

## ระบบงานออกแบบ

### สี (ดูดจากไฟล์โลโก้)

| Token | ค่า | ใช้ที่ไหน |
|---|---|---|
| Mint | `#4FC9A8` | ปลายซ้ายของ gradient, สถานะ "ว่าง" |
| Cyan | `#0FA3CE` | สีหลัก ปุ่ม ลิงก์ |
| Deep Ink | `#0B1E2D` | พื้น section มืด, ตัวอักษรหลัก |

สีทั้งหมดประกาศเป็น CSS custom property แล้วแมปเป็น semantic token
(`--bg`, `--fg`, `--brand`, `--surface`, `--border` …) ที่สลับค่าเองในโหมดมืด
คอมโพเนนต์จึงไม่ต้องเขียน `dark:` ทีละจุด

### โหมดสว่าง/มืด

**ค่าเริ่มต้นคือโหมดมืด** ไม่ได้ตามการตั้งค่าของเครื่อง — เป็นการตัดสินใจเชิงแบรนด์
แต่ถ้าผู้ใช้เคยกดสลับเองไว้ จะยึดตามที่เขาเลือกเสมอ (จำไว้ใน `localStorage`)

มีสคริปต์เล็ก ๆ รันก่อนหน้าจอวาดครั้งแรกเพื่อไม่ให้จอขาวแวบตอนเข้าเว็บ
และ `toggleTheme()` แก้ `meta[name="theme-color"]` ตามไปด้วย ไม่งั้นขอบจอบนมือถือจะคนละโทนกับหน้าเว็บ

### จังหวะสว่าง–มืดของหน้า

**ทั้งเว็บใช้ธีมเดียวกันหมด ไม่มีแถบมืดตายตัวแล้ว**

แถบหัวหน้าทุกหน้าใช้คอมโพเนนต์เดียวกันคือ `src/components/ui/HeroBand.tsx`
ซึ่งใช้ token ของธีม จึงสว่างตามหน้าในโหมดสว่าง และมืดตามหน้าในโหมดมืด
เอกลักษณ์ของแถบมาจาก**ลายตารางกับแสงเรือง** ไม่ใช่จากการสลับสีพื้น
(เดิมชื่อ `DarkBand` และบังคับพื้นเข้มเสมอ ทำให้เว็บที่ตั้งใจให้สว่างเป็นหลักมีแถบมืดคั่นเป็นช่วง ๆ)

Footer ก็ใช้ token เช่นกัน จึงมีทั้งโหมดสว่างและมืด

หน้าแรกเป็นโซนสว่างสองเฉด (`bg` กับ `bg-subtle`) สลับกันเป็น "โซนละสอง section"
ไม่ใช่สลับทุก section เพื่อไม่ให้หน้าเป็นลายทาง

### ตารางจุดที่ตอบสนองเมาส์

`src/components/ui/InteractiveGrid.tsx` วาดทับลายเส้นตารางของ `HeroBand` อีกชั้น
จึงมีผลทั้ง Hero หน้าแรก และแถบหัวหน้า `/guide` กับ `/install`

| การกระทำ | ผลลัพธ์ |
|---|---|
| เลื่อนเมาส์เข้าไปในแถบ | จุดใกล้เคียงสว่างขึ้น โตขึ้น และถูกผลักออกจากเมาส์เล็กน้อย |
| จุดที่ตื่นตัวพร้อมกันและอยู่ติดกัน | เกิดเส้นเชื่อมจาง ๆ เป็นร่างแหเฉพาะรอบเมาส์ ไม่ลากเส้นรกทั้งจอ |
| ปัดเมาส์เร็ว ๆ | เกิดคลื่นวงกลมวิ่งออกไปปลุกจุดที่มันผ่าน |

คุมความแรงไว้ตามบรีฟ — สีมาจาก token ของแบรนด์ ไม่ใช่สีนีออน ระยะผลักแค่ไม่กี่พิกเซล
และไม่มีป้ายตัวเลขหรือกรอบแบบหน้าจอเกม

**ไม่วาดเลย** เมื่อผู้ใช้ตั้งค่า `prefers-reduced-motion` หรือเครื่องไม่มีเมาส์
(`(hover: hover) and (pointer: fine)`) จะเหลือแต่ลายเส้นนิ่ง ๆ ตามเดิม

เรื่องประสิทธิภาพ:
- วาดด้วย canvas ตัวเดียว ไม่ใช่ DOM หลายร้อยชิ้น
- หยุด `requestAnimationFrame` เมื่อทุกจุดจางหมดแล้ว และหยุดเมื่อแถบเลื่อนพ้นจอ
- **เก็บกรอบของแถบไว้ใน ตัวแปร แล้วอัปเดตตอนเลื่อนหน้าเท่านั้น**
  ถ้าเรียก `getBoundingClientRect` ทุกครั้งที่เมาส์ขยับ เบราว์เซอร์จะคำนวณเลย์เอาต์ใหม่
  เป็นร้อยครั้งต่อวินาทีจนหน้าหนืด

### Hero กับแถบเมนู

Hero หน้าแรกสูงเต็มหน้าจอ (`min-h-svh`) และ**พื้นหลังยืดขึ้นไปอยู่ใต้แถบเมนู**
ทำด้วย prop `underHeader` ของ `HeroBand` ซึ่งใส่ margin ติดลบเท่าความสูงแถบเมนู
แล้วใส่ padding ลงมาเท่ากัน — พื้นหลัง ลายตาราง และแสงเรืองจึงเต็มตั้งแต่ขอบบนสุดของจอ
โดยที่เนื้อหายังไม่มุดอยู่ใต้เมนู

แถบเมนูด้านบน**โปร่งใสสนิทตอนยังไม่เลื่อน** จึงกลืนไปกับ Hero
พอเริ่มเลื่อนค่อยมีพื้นเบลอและเส้นขอบ เพื่อให้อ่านออกตอนทับเนื้อหา

### จอกว้างมาก

`.shell` ขยายจาก 76rem เป็น **88rem ที่ 1536px ขึ้นไป** และ `.t-display` ขยายเพดานเป็น 4.6rem
ไม่งั้นบนจอ 1900px ขึ้นไปเนื้อหาจะกระจุกกลางจอแล้วเหลือที่ว่างสองข้างจนดูโล่ง
Hero ยังมีการปรับขนาดเฉพาะ `xl:` เพิ่มอีกชั้น (แผนที่ ตัวเลข ระยะห่าง)

### Typography

ใช้ **LINE Seed Sans TH** ทั้งเว็บ ไฟล์ WOFF2 อยู่ใน `public/fonts/`
น้ำหนักที่มีจริงคือ 300 / 400 / 700 / 800 / 900
จึงหลีกเลี่ยงการใช้ 500 และ 600 เพราะไม่มีไฟล์จริงและเบราว์เซอร์จะแทนด้วยน้ำหนักอื่น

ลำดับขนาดตัวอักษรกำหนดเป็นคลาสใน `globals.css`:
`.t-display` `.t-h1` `.t-h2` `.t-h3` `.t-body-lg` `.t-body` `.t-body-sm` `.t-caption` `.t-button` `.t-nav` `.t-overline`

`line-height` ของ body ตั้งไว้ที่ 1.75–1.8 และหัวเรื่อง 1.22–1.45
ซึ่งสูงกว่าเว็บภาษาอังกฤษทั่วไป เพราะภาษาไทยมีสระบนซ้อนวรรณยุกต์ได้สองชั้น
(เช่น "ที่" "ตั้ง") ถ้าใช้ค่าแน่นแบบอังกฤษบรรทัดจะชนกัน

**นโยบายน้ำหนักตัวอักษร** — ฟอนต์ไทยที่ 700 ขึ้นไปดูหนากว่าอังกฤษที่น้ำหนักเดียวกันมาก
อ่านยาว ๆ แล้วล้าตา จึงคุมไว้ว่า:

- `800` ใช้เฉพาะ `.t-display` (หัวเรื่องใหญ่สุดของหน้า)
- `700` ใช้กับหัวเรื่องรอง ปุ่ม เมนูที่กำลังเลือกอยู่ และชื่อหลักของการ์ด
- `400` ใช้กับทุกอย่างที่เหลือ รวมถึงป้ายกำกับ แท็ก และข้อความขนาดเล็ก
- **การเน้นระดับกลางใช้ "สี" แทน "น้ำหนัก"** เพราะฟอนต์ชุดนี้ไม่มีน้ำหนัก 500/600
  ถ้าเผลอเขียน `font-medium` หรือ `font-semibold` เบราว์เซอร์จะไปหยิบ 400 หรือ 700 มาแทน

### ⚠️ กับดัก: คลาส Tailwind ที่ชนกันเอง

**อย่า override สีหรือการแสดงผลของคอมโพเนนต์ด้วย `className`**
เพราะ utility ของ property เดียวกัน (เช่น `text-white` กับ `text-[...]`, `hidden` กับ `inline-flex`)
มี specificity เท่ากัน ตัวที่ชนะคือตัวที่อยู่**หลังกว่าในไฟล์ CSS** ไม่ใช่ตัวที่อยู่หลังกว่าใน class attribute

เคยพังมาแล้วสองครั้ง:
- ปุ่มบนพื้นไล่สี — `text-white` ของ variant ชนะสีที่ override ไป ตัวอักษรหายเป็นขาวบนขาว
- ปุ่ม CTA บนแถบเมนู — `hidden` แพ้ `inline-flex` ปุ่มไม่ถูกซ่อนบนมือถือ แถบเมนูล้นจนปุ่มแฮมเบอร์เกอร์หลุดจอ

วิธีที่ถูกคือ**เพิ่ม variant ใหม่ให้คอมโพเนนต์** (เช่น `variant="onColor"` สำหรับปุ่มขาวบนพื้นไล่สี)
หรือ**ครอบด้วย element อื่น** (เช่น `<span className="hidden md:block">`)

**ข้อควรระวังเวลาใช้ตัวอักษรไล่สี** — `background-clip: text` วาดสีเฉพาะในกรอบกล่องของ element
สระบนและวรรณยุกต์ไทยที่ยื่นพ้นกรอบบรรทัดขึ้นไปจะไม่ถูกวาดสี แล้วดูเหมือนถูกตัดหาย
แก้แล้วด้วยการยืดกรอบด้วย `padding-block` แล้วดึงกลับด้วย `margin-block` ติดลบ
ในคลาส `.brand-gradient-text` และ `.rc-aurora` — **ถ้าจะทำคลาสไล่สีใหม่ ต้องใส่ด้วยทุกครั้ง**

### แผนที่ประเทศไทย

ใช้ **ขอบเขตการปกครองจริงทั้ง 77 จังหวัด** ไม่ใช่รูปทรงที่วาดประมาณเอา

- แหล่งข้อมูล: [apisit/thailand.json](https://github.com/apisit/thailand.json)
- `scripts/build-thailand-geo.mjs` ดาวน์โหลด ฉายพิกัดลงระนาบ และลดจำนวนจุด
  จาก 26,709 เหลือ 6,192 จุด (คลาดเคลื่อนไม่เกิน 0.32 พิกเซลบนแผนที่)
  แล้วเขียนผลลงไฟล์ `src/data/thailand-geo.ts` ซึ่ง**ห้ามแก้ด้วยมือ**
- สร้างใหม่ได้ด้วย `node scripts/build-thailand-geo.mjs`
- `src/data/geo.ts` เอาข้อมูลนั้นมาผูกกับการแบ่งภาคและพิกัดตัวเมือง

ตัวแผนที่ (`src/components/map/ThailandMap.tsx`) ทำงาน 3 ระดับ:

1. **ทั้งประเทศ** — ระบายสีรายจังหวัดตามจำนวนสถานี + ฟองตัวเลขรวมรายภาค
2. **รายภาค** — ซูมเข้าไปเห็นชื่อจังหวัดและจำนวนสถานีของแต่ละจังหวัด
3. **รายจังหวัด** — จังหวัดที่เลือกถูกไฮไลต์ พร้อมหมุดรายสถานี
   และคลี่หมุดที่อยู่ใกล้กันเกินไปออกเป็นวงกลม
   ไม่งั้นสถานีในตัวเมืองเดียวกันจะทับกันจนกดไม่ได้

การไฮไลต์ภาคตอนเอาเมาส์ชี้ทำด้วย CSS ล้วน ไม่ใช่ React state
เพราะจังหวัดทั้ง 77 รูปมีจุดรวมกันหกพันกว่าจุด ถ้าให้ React วาดใหม่ทุกครั้งที่เมาส์ขยับจะหน่วง

**ท่าทางบนแผนที่** (`src/components/map/useMapGestures.ts`)

| ท่าทาง | ผลลัพธ์ |
|---|---|
| ลากนิ้ว / ลากเมาส์ | เลื่อนแผนที่ |
| หนีบสองนิ้ว | ซูมเข้า–ออก โดยตรึงจุดกึ่งกลางระหว่างนิ้วไว้กับที่ |
| หมุนล้อ / trackpad | ซูมเข้าหาตำแหน่งเมาส์ |
| ปุ่ม + / − | ซูมจากกึ่งกลางจอ |

หน้า `/stations` สูงเท่าหน้าจอพอดีและไม่มี footer ล้อเมาส์จึงเป็นการซูมแผนที่อย่างเดียว

**ห้ามเรียก `setPointerCapture` ตอน `pointerdown`** — เมื่อ pointer ถูกจับไว้ที่ `<svg>`
เบราว์เซอร์จะส่ง `click` ไปที่ `<svg>` แทนรูปจังหวัดที่อยู่ข้างใน ทำให้กดเลือกภาค/จังหวัดไม่ได้เลย
โค้ดจึงไปจับเอาตอนที่ผู้ใช้ลากเกิน 6 พิกเซลแล้วเท่านั้น

ตัว `<svg>` ตั้ง `select-none` ไว้ ไม่งั้นการลากแผนที่จะกลายเป็นการลากเลือกข้อความของป้ายชื่อ

### หน้าค้นหาบนมือถือ

ยกแพตเทิร์นมาจากแอป Google Maps บนมือถือ (`src/components/ui/BottomSheet.tsx`)

- **แผนที่เต็มจอ** ทุกอย่างลอยทับคนละชั้น ไม่กินที่ในผังของแผนที่ —
  แถบค้นหากับชิปตัวกรองลอยด้านบน ปุ่ม "ใกล้ฉัน" กับปุ่มซูมลอยทับแผนที่
  ปุ่มใกล้ฉันเลื่อนขึ้นลงตามแผ่นเลื่อนผ่านตัวแปร `--rc-sheet-h`
- **แผนที่ขยายตามแผ่นเลื่อน** — ที่ว่างด้านล่างของแผนที่ผูกกับความสูงจริงของแผ่นเลื่อน
  (`.rc-map-frame` ใน globals.css) ลากแผ่นลง แผนที่โตขึ้นทันที
  วัดจริงที่จอ 375×812: ครึ่งจอ 392px → แอบโผล่ **524px** (โตขึ้น 132px)
  ไม่ใช่ค่าคงที่ที่ทิ้งที่ว่างเปล่า ๆ ไว้ระหว่างแผนที่กับแผ่นเลื่อนแบบเดิม
- **แผ่นเลื่อนมีสามจุดหยุด** — แอบโผล่ 14% / ครึ่งจอ 50% / เต็มจอ 92%
  ระดับกลางเป็นค่าเริ่มต้นเพราะเห็นทั้งแผนที่และรายการพร้อมกัน
- **กดหมุดบนแผนที่** แผ่นเลื่อนเปลี่ยนเป็นรายละเอียดสถานีที่ระดับครึ่งจอ อยากอ่านต่อก็ลากขึ้น

สามเรื่องที่ทำให้แผ่นเลื่อนรู้สึกเหมือนของจริง และเป็นจุดที่คนมักทำหลุด:

1. **ลากแล้วตามนิ้วทันที** — เขียน `transform` ลง DOM ตรง ๆ ระหว่างลาก ไม่ผ่าน React state
   ถ้าผ่าน state จะต้อง re-render ทุกเฟรมแล้วหน่วง
2. **ปล่อยแล้วดูความเร็ว ไม่ใช่ดูแค่ตำแหน่ง** — สะบัดเร็ว ๆ ต้องข้ามไปจุดถัดไป
   แม้นิ้วจะขยับไปไม่ถึงครึ่งทาง
3. **เนื้อหาเลื่อนได้เฉพาะตอนแผ่นสุดแล้ว** — ถ้ายังไม่สุด การลากในเนื้อหาคือการลากตัวแผ่น
   ไม่งั้นผู้ใช้จะงงว่าทำไมบางทีลากแล้วแผ่นขยับ บางทีไม่ขยับ

### แผงรายละเอียดสถานี

จัดวางแบบเดียวกับ Google Maps คือมีสองระดับ ไม่ใช่แผงเดียวสลับเนื้อหา

| ขนาดจอ | พฤติกรรม |
|---|---|
| `lg` ขึ้นไป | เปิดเป็น **แผงที่สอง** ต่อจากรายการทางซ้าย รายการยังอยู่ให้เห็น กดสลับดูสถานีอื่นได้เลย |
| `md` | ที่ไม่พอวางสองแผง จึงทับรายการไปในกรอบเดิม |
| มือถือ | ไม่ใช้คอมโพเนนต์นี้ — แสดงในแผ่นเลื่อนด้านล่างแทน (ดูหัวข้อด้านบน) |

ทุกกรณี**ไม่มีฉากมืดคลุม** แผนที่ยังใช้งานได้เต็มที่ และแผนที่จะเลื่อนหลบให้พ้นแผงที่สองเองเมื่อเปิดอยู่

ทิศทางอนิเมชันเปลี่ยนตามตำแหน่งจริงของแผง — มือถือเลื่อนขึ้น จอใหญ่เลื่อนเข้ามาจากซ้าย
ไม่งั้นจะรู้สึกว่าของกระโดดมาผิดทาง

**เรื่องรีวิว** — ตามที่ตกลงกันไว้ รีวิวทั้งหมดเขียนโดยทีมงานหลังบ้านเพียงแหล่งเดียว
การโชว์เป็น "คะแนน 4.8 จาก 241 รีวิว" จึงทำให้เข้าใจผิดว่าเป็นความเห็นจากผู้ใช้หลายคน
**จึงเอาแท็บรีวิวและแถบคะแนนออกทั้งหมด** (ข้อมูลยังอยู่ใน `stations.ts` เผื่อเปลี่ยนใจภายหลัง)

บนการ์ดผลการค้นหา **ไม่โชว์จำนวนหัวว่าง** เพราะเป็นตัวเลขที่เปลี่ยนตลอดเวลา
เห็นตอนเปิดรายละเอียดก็ทันการณ์กว่า — พื้นที่ตรงนั้นให้กับ**สิ่งอำนวยความสะดวกรอบ ๆ สถานี**
ซึ่งเป็นสิ่งที่ใช้ตัดสินใจว่าจะแวะที่ไหนมากกว่า

ทั้งหมดทำงานบนค่า `viewBox` โดยตรง ไม่ใช้ CSS transform
เพราะเส้นขอบและตัวอักษรคำนวณขนาดจาก `viewBox` อยู่แล้ว
ถ้าไปสเกลด้วย transform เส้นจะหนาขึ้นตามและตัวหนังสือจะเบลอ

แผนที่บนหน้าแรกฝังอยู่ในหน้าที่เลื่อนได้ จึงตั้ง `wheelMode="modifier"`
คือต้องกด Ctrl/⌘ ค้างก่อนจึงจะซูมด้วยล้อได้ ไม่งั้นจะไปแย่งการเลื่อนหน้า

ขนาดตัวอักษรและหมุดคำนวณจากขนาดกล่องจริง (ResizeObserver)
จึงคงขนาดบนจอเท่าเดิมเสมอไม่ว่าจะซูมเข้าไปแค่ไหน

## ข้อมูลที่ต้องเปลี่ยนก่อนใช้จริง

ทุกไฟล์ใน `src/data/` มีหมายเหตุกำกับไว้ด้านบนแล้วว่าส่วนไหนเป็นข้อมูลสมมติ

| ไฟล์ | สถานะ | สิ่งที่ต้องทำ |
|---|---|---|
| `site.ts` | 🔴 **ทั้งไฟล์เป็น placeholder** | เบอร์โทร อีเมล LINE Facebook ที่อยู่ เวลาทำการ — ยังไม่ได้รับข้อมูลจริง |

| `install.ts` | 🟠 โครงถูก เนื้อหาสมมติ | รายการบริการ ขั้นตอน 4 สเต็ป และผลงาน 9 ชิ้น ต้องให้ทีมงานยืนยัน |
| `apps.ts` | 🟠 ชื่อจริง ตัวเลขสมมติ | จำนวนสถานี วิธีจ่ายเงิน และจุดเด่นของแต่ละแอป ต้องตรวจกับผู้ให้บริการ |
| `posts.ts` | 🟠 เนื้อหาตัวอย่าง | เขียนเนื้อหาเต็มไว้ 3 บทความ ที่เหลือเป็นโครง |
| `geo.ts` | 🟢 พิกัดจริง | ขอบเขตภาคเป็นรูปแบบสไตไลซ์ ไม่ใช่ขอบเขตการปกครองที่แม่นยำ |

**ตามที่ตกลงกันไว้ หน้าเว็บไม่มีป้ายกำกับว่าเป็น mock data** เพื่อให้ดูเหมือนของจริงตอนนำเสนอ
บันทึกไว้ที่ไฟล์นี้แทน

### เรื่องที่ยังไม่มีในต้นแบบนี้

- ไม่มีระบบหลังบ้าน — ฟอร์มติดต่อตรวจความถูกต้องแล้วแสดงผลในหน้า ไม่ได้ส่งข้อมูลไปที่ใด
- สถานะหัวชาร์จว่าง/ไม่ว่าง เป็นค่าคงที่ ไม่ได้อัปเดตแบบเรียลไทม์
- ระบบรีวิวเป็นแบบอ่านอย่างเดียว (ตามที่ตกลงว่าทีมงานเป็นคนรีวิวเองจากหลังบ้าน)
- **เว็บเป็นภาษาไทยอย่างเดียว** — ลบปุ่มสลับ TH/EN ออกทั้งจาก Header และเมนูมือถือแล้ว
  ระบบแปล (`src/lib/i18n.tsx`) ยังอยู่ครบและถูกใช้ผ่าน `t()` ทั่วเว็บ
  ถ้าจะเปิดภาษาอังกฤษภายหลัง ทำปุ่มใหม่ที่เรียก `setLocale()` ได้เลย
- **ไม่เก็บข้อมูลจำนวนหัวที่ว่างอยู่ตอนนี้** — ถอดออกทั้งชุดข้อมูลและหน้าเว็บแล้ว
  (ตัวกรอง "เฉพาะที่มีหัวว่าง", ตัวเลือกเรียง "หัวว่างมากที่สุด", ป้ายสถานะบนการ์ดและในแผงรายละเอียด)
  เพราะเป็นค่าที่ต้องต่อกับระบบของแต่ละเครือข่ายแบบเรียลไทม์
  ถ้าเก็บเป็นค่านิ่ง ๆ ไว้จะกลายเป็นข้อมูลที่ผิดเกือบตลอดเวลา
  ตอนนี้แสดงเป็น "จำนวนหัวชาร์จที่มี" แทน ซึ่งเป็นค่าที่นิ่งและตรวจสอบได้
- ยังไม่ได้ระบุยี่ห้อเครื่องชาร์จที่จำหน่าย — ใช้การอธิบายด้วยสเปกแทน

## GPS / ปุ่ม "ใกล้ฉัน"

เบราว์เซอร์ยอมให้อ่านตำแหน่งเฉพาะหน้าที่เปิดผ่าน **https หรือ localhost** เท่านั้น

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| ขึ้นว่าสิทธิ์ถูกปิดไว้ | เคยกดปฏิเสธไว้ หรือเบราว์เซอร์ตั้งค่าบล็อกไว้ | กดไอคอนหน้าช่องที่อยู่เว็บ → ตำแหน่งที่ตั้ง → อนุญาต แล้วรีเฟรช |
| ขึ้นว่าหาตำแหน่งไม่เจอ | ระบบปฏิบัติการปิดบริการระบุตำแหน่ง | macOS: System Settings → Privacy & Security → Location Services → เปิดให้เบราว์เซอร์ |
| ขึ้นว่าเชื่อมต่อไม่ปลอดภัย | เปิดผ่าน IP ในวงแลน เช่น `http://192.168.x.x:3000` | ใช้ `pnpm dev:https` แล้วเปิดผ่าน `https://` แทน |

**ทดสอบบนมือถือจริง** — รันด้วย HTTPS เพราะเปิดผ่าน IP แบบ http เบราว์เซอร์จะปิดกั้นตั้งแต่ต้น

```bash
pnpm dev:https
```

ครั้งแรกจะสร้างใบรับรองแบบ self-signed ให้เอง เปิดบนมือถือแล้วจะเจอหน้าเตือนว่าใบรับรองไม่น่าเชื่อถือ
ให้กดยอมรับเพื่อเข้าต่อ (ปลอดภัยเพราะเป็นเครื่องตัวเองในวงแลนเดียวกัน)

ข้อความแจ้งเตือนในหน้าเว็บแยกตามสาเหตุจริงทั้งสามแบบแล้ว พร้อมปุ่มลองใหม่
ไม่ใช่ข้อความเดียวที่บอกแค่ว่าอ่านตำแหน่งไม่ได้

## รูปตัวอย่างตอนแชร์ลิงก์ (Open Graph)

`public/og.png` (1200×630) คือรูปที่ขึ้นเวลามีคนแปะลิงก์เว็บนี้ใน LINE / Facebook / X / Slack

```bash
node scripts/build-og-image.mjs
```

**ทำไมไม่ใช้ `next/og` ที่เป็นวิธีมาตรฐานของ Next**

ตัวนั้นวาง**วรรณยุกต์ที่ซ้อนอยู่บนสระ**ของภาษาไทยไม่ได้ — ทดสอบแล้วคำว่า "ที่" ออกมาเป็น "ที"
และ "ตั้ง" ออกมาเป็น "ตัง" ซึ่งอ่านผิดความหมาย
จึงเปลี่ยนมาวาดด้วย `rsvg-convert` ที่จัดรูปอักษรไทยได้ถูกต้อง (ต้อง `brew install librsvg`)

ผลลัพธ์เป็น**ไฟล์นิ่งที่เก็บลง git** ไม่ได้สร้างตอน deploy เพราะเครื่อง deploy ไม่มี rsvg-convert
รันสคริปต์ใหม่เฉพาะตอนเปลี่ยนโลโก้หรือข้อความ

### ⚠️ ต้องติดตั้งฟอนต์ลงเครื่องก่อน

```bash
cp src/assets/fonts/*.ttf ~/Library/Fonts/ && fc-cache -f
```

**`rsvg-convert` ไม่สนใจตัวแปร `FONTCONFIG_FILE`** — พิสูจน์แล้วด้วยการชี้ config
ไปที่โฟลเดอร์ว่างที่ไม่มีฟอนต์เลย (`fc-list` เห็น 0 ฟอนต์) แต่มันยังวาดภาษาไทยออกมาได้
และได้ภาพ **md5 ตรงกันเป๊ะ** กับตอนชี้ไปที่ LINE Seed จริง ๆ
แปลว่ามันอ่านฟอนต์จากระบบเท่านั้น ชี้ให้อ่านจากในโปรเจกต์โดยตรงไม่ได้

ผลคือเวอร์ชันแรกของ `og.png` ถูกวาดด้วยฟอนต์ไทยของ macOS ไปโดยไม่มีใครรู้
เพราะทุกอย่างดู "ผ่าน" หมด — `fc-match` ตอบชื่อไฟล์ถูก ทั้งที่ `rsvg-convert` ใช้ฟอนต์อื่น

**ด่านตรวจในสคริปต์** จึงไม่ใช้ `fc-match` แต่วาดจริง 2 รอบเทียบกัน:
รอบหนึ่งใช้ชื่อฟอนต์จริง อีกรอบใช้ชื่อฟอนต์ที่ไม่มีอยู่จริง
ถ้าได้ภาพเหมือนกันเป๊ะ = ชื่อจริงก็โดน fallback เหมือนกัน → โยน error ทิ้งพร้อมบอกวิธีติดตั้ง

**ไฟล์ฟอนต์ในโปรเจกต์มีสองชุด** เป็นตัวเดียวกัน คนละรูปแบบไฟล์:

| ใครใช้ | ไฟล์ | หมายเหตุ |
|---|---|---|
| เบราว์เซอร์ (`next/font/local`) | `public/fonts/*.woff2` | ชุด Web จากผู้ผลิต |
| สคริปต์สร้าง og.png (`rsvg-convert`) | `src/assets/fonts/*.ttf` | ชุด Desktop ใช้เป็นต้นฉบับไว้ติดตั้งลงเครื่อง |

ทั้งสองชุดมาจากไฟล์ `LINE_Seed_Sans_TH_V1.003` เหมือนกัน ทดสอบเรนเดอร์เทียบกันแล้วตัวอักษรตรงกัน
ที่ต้องแยกเพราะ **fontconfig อ่าน `.woff2` ไม่ได้** เลยติดตั้งไฟล์ชุดที่เว็บใช้ลงเครื่องตรง ๆ ไม่ได้

มีครบทั้ง 5 น้ำหนัก (300/400/700/800/900) แต่ในรูปใช้แค่ 400 กับ 800

**ข้อความในรูปนี้ใส่ได้เฉพาะสิ่งที่ไม่เปลี่ยน**

รูปถูกแคชไว้ตามแอปแชตต่าง ๆ แก้แล้วกว่าจะอัปเดตตามกันหมดใช้เวลาเป็นวัน บางที่ไม่อัปเดตเลย

| ใส่ได้ | ห้ามใส่ |
|---|---|
| ชื่อแบรนด์ สโลแกน คำอธิบายว่าเว็บทำอะไร | ตัวเลขทุกชนิด (จำนวนสถานี จังหวัด ผลงาน) |
| | คำสัญญาทางธุรกิจที่ยังไม่ยืนยัน (ราคา เงื่อนไขบริการ) |

**`og:image` ต้องเป็น URL เต็ม** `src/app/layout.tsx` จึงไล่หาที่อยู่เว็บตามลำดับนี้

1. `NEXT_PUBLIC_SITE_URL` — ตั้งเองเมื่อมีโดเมนจริง
2. `VERCEL_PROJECT_PRODUCTION_URL` — Vercel ใส่ให้เอง ไม่ต้องตั้งอะไร
3. `http://localhost:3000` — ตอนพัฒนา

บน Vercel จึงใช้ได้เลยโดยไม่ต้องตั้ง env ค่อยเพิ่มข้อ 1 ตอนย้ายไปโดเมนของตัวเอง

## ไอคอนและ manifest

| ไฟล์ | ใช้ที่ไหน |
|---|---|
| `src/app/icon.svg` | favicon หลัก (เบราว์เซอร์สมัยใหม่) |
| `src/app/apple-icon.png` | 180×180 สำหรับ iOS |
| `public/favicon.ico` | 16/32/48 สำหรับเบราว์เซอร์เก่าและตัวเก็บ bookmark |
| `public/brand/icon-192.png`, `icon-512.png` | ไอคอนแอปใน manifest |
| `src/app/manifest.ts` | ชื่อ ไอคอน และสีตอน "เพิ่มไปยังหน้าจอโฮม" |

รวมทุกไฟล์ 60 KB

**ไอคอนมีสองรุ่น** — รุ่นเต็มกรอบใช้กับ favicon กับ iOS ส่วนรุ่นที่ย่อตัวสัญลักษณ์ลงเหลือ 74%
ใช้กับ manifest เพราะ Android ครอบไอคอนเป็นวงกลมหรือทรงอื่นตามธีมเครื่อง
ถ้าใช้รุ่นเต็มกรอบ ตัวสัญลักษณ์จะโดนตัดขอบ

ตัวไอคอนตัดรายละเอียดของโลโก้เต็มออกบางส่วน (หัวลูกศรและสายฟ้าเส้นที่สอง)
เพราะที่ขนาด 16px รายละเอียดพวกนั้นกลายเป็นก้อนเลอะ อ่านไม่ออก

สร้างใหม่จาก SVG ได้ด้วย `rsvg-convert` (ดูขนาดในตารางข้างบน)

## โลโก้แอปชาร์จ

ไฟล์อยู่ใน `public/brand/apps/<id>.png` (10 ไฟล์ รวม 64 KB)
ดึงมาจาก**ไอคอนแอปทางการ**ผ่าน iTunes Search API ของ Apple เพราะบริการเหล่านี้เป็นแอปมือถือ
ไอคอนแอปจึงเป็นโลโก้ที่เจ้าของแบรนด์เผยแพร่เอง

```bash
node scripts/fetch-app-logos.mjs
```

> ⚠️ **โลโก้ทุกอันเป็นเครื่องหมายการค้าของเจ้าของแบรนด์**
> การนำมาแสดงในหน้ารวมข้อมูลถือเป็นการอ้างถึงตามปกติของเว็บประเภท directory
> แต่**ควรแจ้งหรือขออนุญาตเจ้าของแบรนด์ก่อนเผยแพร่จริง**

**สองรายการที่เคยสงสัยว่าจับคู่ผิด — ตรวจแล้วถูกทั้งคู่**

| แบรนด์ | แอปที่จับคู่ไว้ | หลักฐาน |
|---|---|---|
| SHARGE | "Recharge - EV Charging" (`com.sharge.rechargeapp`) | ผู้เผยแพร่คือ Sharge Management Company Limited ตรงกับเจ้าของ `sharge.co.th` ชื่อแอปไม่ตรงกับชื่อเครือข่ายเฉย ๆ |
| iGreen+ | "iGreen+" (`io.csenergy`, App Store id `6459449843`) | เว็บทางการ `igreenplus.co.th` ของ iGreen Plus Co., Ltd ลิงก์ไปที่ id นี้ตรง ๆ ที่ผู้เผยแพร่เป็น Shenzhen CS Energy Technology เพราะเป็นเจ้าของแพลตฟอร์มที่ iGreen+ เอามาใช้ |

ถ้าจะตรวจซ้ำเอง เรียก API นี้แล้วดู `sellerName` กับ `bundleId`:

```bash
curl -s "https://itunes.apple.com/lookup?id=6459449843&country=th" | python3 -m json.tool
```
